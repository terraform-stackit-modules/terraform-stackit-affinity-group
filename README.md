# Terraform STACKIT Affinity Group module

Terraform module which creates [STACKIT server affinity groups](https://registry.terraform.io/providers/stackitcloud/stackit/latest/docs/resources/affinity_group) on [STACKIT](https://www.stackit.de/en/) to control the placement of a *group* of servers relative to each other (affinity / anti-affinity).

This is a small, dedicated module: an affinity group is inherently **multi-server** (it constrains how a set of VMs are scheduled across compute nodes), so it lives on its own rather than inside the single-server `terraform-stackit-compute` module. Create the group here, then pass its ID to the `affinity_group` input of several compute servers.

This repository is not from the official STACKIT organization.

## Usage

```hcl
module "affinity_group" {
  source  = "terraform-stackit-modules/affinity-group/stackit"
  version = ">= 1.0.0"

  project_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

  affinity_groups = {
    web_ha = {
      name   = "web-anti-affinity"
      policy = "soft-anti-affinity"
    }
  }
}

# Then, on each compute server that should be spread apart:
# module "web_1" {
#   source         = "terraform-stackit-modules/compute/stackit"
#   ...
#   affinity_group = module.affinity_group.affinity_group_ids["web_ha"]
# }
```

See [`examples/basic`](./examples/basic) for a self-contained example (requires only `project_id`).

## Policies

- `hard-affinity` — all servers in the group MUST be hosted on the same compute node.
- `hard-anti-affinity` — all servers in the group MUST be hosted on different compute nodes.
- `soft-affinity` — prefer the same compute node, but still schedule if not possible.
- `soft-anti-affinity` — prefer different compute nodes, but still schedule if not possible (typical HA).

## Notes

- `affinity_groups` is a map keyed by a **stable identifier**; `policy` is validated against the
  four values above.
- The group only takes effect once servers reference its ID via their `affinity_group` input.
